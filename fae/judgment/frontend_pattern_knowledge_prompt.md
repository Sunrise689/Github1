# FAE 后端 → 前端形态知识库提示词

这是 FAE 后端发送给前端形态知识库和K线图层的唯一正式说明文件。

前端工程师只需要读取本文件，不要根据旧文档、旧截图或旧名称自行推断规则。后端每次修改形态定义、名称、别名、显示方式或确认条件时，都必须：

1. 修改本文件的 `contract_version`；
2. 更新 `updated_at`；
3. 在文末“后端更新日志”追加一条记录；
4. 保留旧名称时，只能作为兼容别名，不能重新变成正式形态。

## 一、前端接收事件的统一字段

前端应按以下字段读取后端事件：

```json
{
  "contract_version": "1.1.0",
  "updated_at": "2026-08-01 16:58:56 +08:00",
  "pattern_id": "red_three_soldiers",
  "display_name": "红三兵",
  "variant": null,
  "direction": "bullish",
  "state": "candidate",
  "confidence": 0.80,
  "start": 120,
  "end": 122,
  "explanation": "三根连续创新高的小阳线",
  "aliases": [],
  "geometry": {"lines": [], "arcs": [], "pivots": []},
  "trade_point": null,
  "suppressed": []
}
```

字段要求：

- `pattern_id` 用于统计、去重、评分和冲突消解；
- `display_name` 用于界面展示；
- `variant` 只用于展示强弱变体，不产生新的统计形态；
- `state` 使用 `candidate`、`confirmed`、`degraded`、`invalidated`；
- `confidence` 为 0 到 1 的数值；
- 同一 `pattern_id + start + end` 只能显示一条记录。
- 技术图形必须同时提供 `geometry`；只有 `state=confirmed` 且确实发生有效突破时才允许填充 `trade_point`，否则保持 `null`。
- `suppressed` 用于记录同一位置被互斥规则压掉的候选，不再重复绘制。

当前内部 `DetectedSignal` 保留旧的 `pattern` 字段用于兼容；前端应优先读取序列化后的 `pattern_id`，并使用 `variant` 表示复合/多重/三角旗等变体，不要把旧中文别名或旧 `pattern` 值当作新的 canonical ID。

## 二、FAE 三层流水线顺序

前端展示必须尊重以下顺序：

1. **第一层：量化过滤**——用滚动收益分位数、趋势斜率、波动率和基本密度约束，先排除统计上不可能或明显不合理的候选；
2. **第二层：案例库/数据库**——只对通过量化过滤的候选检索历史案例，案例不能把被量化层否决的形态重新激活；
3. **第三层：人工判断**——当前尚未实现，后续由用户结合当前行情做最终裁定。

量化层使用约 100～120 根K线的向后滚动窗口：上涨/下跌背景按当前窗口收益处于历史滚动分布的上/下分位数并结合斜率判定，不要求每一根K线都是“大涨”或“大跌”。

## 三、红三兵统一规则

请将“红三兵”和“三个白色武士”作为同一个基础K线形态处理，不建立两张独立形态卡片，也不重复统计。

- 正式显示名称：`红三兵`
- canonical pattern_id：`red_three_soldiers`
- 中文兼容别名：`三个白色武士`、`三白兵`
- “三个白色武士”仅表示红三兵的强势变体，不是第二个独立形态。
- 普通红三兵：三根连续创新高的小阳线，收盘价逐根抬高。
- 强势变体：三根连续阳线逐根收高，收盘位于各自最高点或接近最高点，上影线较短。
- 统计、评分、冲突消解、案例计数全部使用 `red_three_soldiers`。

前端显示：

- 普通识别：`红三兵`
- 满足强势变体：`红三兵（强势变体：三个白色武士）`
- 若后端同时返回两个名称，前端必须合并为一条记录，并保留强势变体标签。

## 四、术语统一

- 正式术语使用“缺口/GAP”。
- “上升窗口”“下降窗口”只作为历史数据兼容别名，不得作为新形态卡片标题。
- “锤子线”为正式名称；“锤头线”只作为旧别名。

## 五、已确认的形态规则

### 1. 锤子线

- `pattern_id`: `hammer`
- 正式名称：`锤子线`
- 旧别名：`锤头线`
- 必须处于下跌背景；
- 必须有明显长下影线、较小实体；
- 确认窗口由第一层量化上下文自适应确定（100～120根K线时通常约 5 根，范围限制为 2～8 根），不是固定 3 根；
- 确认窗口内所有收盘价不得跌破锤子线下影线最低点；
- 未满足后续确认时，只显示候选，不显示为已成立形态。

### 2. 吊颈线

- `pattern_id`: `hanging_man`
- 必须处于明显上涨背景；
- 必须有长下影线和较小实体；
- 确认窗口由第一层量化上下文自适应确定（100～120根K线时通常约 5 根，范围限制为 2～8 根），不是固定 3 根；
- 确认窗口内必须有K线跌破其下影线最低点；
- 只出现形状但没有后续跌破时，不显示为已成立的吊颈线。

### 3. 连续跳空三阳线 / 连续跳空三阴线

- `连续跳空三阳线` → `three_gap_up`
- `连续跳空三阴线` → `three_gap_down`
- 必须由三根同方向K线组成；
- 三阳线：后一根开盘价高于前一根收盘价；
- 三阴线：后一根开盘价低于前一根收盘价；
- 允许影线重叠，不要求每个影线之间都形成完整 high/low 缺口；
- 不能因为影线重叠而否定实体开盘价条件。

### 4. 倒三阳

- `pattern_id`: `three_reverse_bullish`
- 只在下降过程中识别；上涨背景不识别为倒三阳；
- 经典形式：三根实体为阳线，但后续阳线低于前一根收盘价开盘，三根收盘价和实体中点逐根下移；也就是“外观收阳、价格重心仍在下移”，不能把上涨中的连续阳线标成倒三阳；
- 量化闸门必须同时确认近期和较宽窗口的下降背景；只是一段上涨中的短暂回调不得通过；
- 放宽形式：两根低开阳线，或两根低开阳线中间夹一根阴线；这两类只能在解释中标注“放宽变体”，不能冒充标准三根阳线；
- FAE 层若发现收盘/实体中点上移、背景为上涨或缺少低开条件，必须拒绝该候选；统计仍使用同一个 `pattern_id`，但拒绝原因必须写入量化过滤结果。

### 5. 升势停顿 / 停顿形态

- `pattern_id`: `rise_pause`
- 中文显示：`停顿形态`；教材别名：`升势停顿`；
- 出现在上涨过程中；
- 三根阳线，前两根为较大或中等实体，后续实体逐步缩小；
- K线应有可见上影线或下影线；
- 与红三兵是不同形态，不得合并统计。

### 6. 弃婴十字星

- 看涨：`bullish_abandoned_baby`
- 看跌：`bearish_abandoned_baby`
- 中间K线必须是十字星；
- 第一根和第三根不强制要求大阳线/大阴线，小实体和纺锤线可以进入候选；
- 当前正式规则默认要求第一根和第三根不是十字星，以避免与三星形混淆；
- 十字星与左侧K线之间必须有真实缺口；
- 十字星与右侧K线之间必须有反向真实缺口；
- 两侧影线不能与中间十字星重叠；
- 只有一侧缺口时，降级识别为早晨十字星或黄昏十字星，不得显示为弃婴十字星。

待用户确认：如果第一根和第三根本身也可以是十字星，需单独作为“三星形/弃婴变体”处理，不能直接无条件并入严格弃婴十字星。

## 六、技术图形 canonical 规则

### 1. 多重顶底

- `double_top` / `double_bottom` 是主形态；`triple_top`、`triple_bottom`、多峰、多谷只作为 `variant=multiple`。
- 仍需颈线有效突破确认；变体不单独生成统计卡片。

### 2. 复合头肩

- 主 ID 仍为 `head_and_shoulders_top` 或 `head_and_shoulders_bottom`。
- 复合结构使用 `variant=compound`，不使用独立统计 ID。

### 3. V 形顶底

- `v_bottom` 为尖底/V形底；`inverted_v_top` 为尖顶/倒V形顶。
- `v_top` 仅作为旧案例兼容别名。

### 4. 收敛三角形与三角旗

- `symmetrical_triangle` 是唯一 canonical ID。
- `pennant`、`三角旗`、`三角旗形`作为兼容别名/变体；未确认突破前不得输出买卖点。

### 5. 箱形整理

- `rectangle` 是唯一 canonical ID，显示名称为“箱形整理”。
- “矩形”“箱体”“整理区间”“菱形”“钻石形”“菱形顶”均为兼容别名或历史变体；不得再单独输出 `diamond`。

### 6. 潜伏底

- `dormant_bottom`：明显下跌后的狭幅、低量、较长时间筑底。
- 突破箱体上沿并通过时间/量能确认后，才输出买点；未突破时仅为候选。

### 7. 杯柄形态

- `cup_with_handle`：相近杯口、中央圆弧杯底、浅幅柄部回撤。
- 柄部不得深跌回杯底；买点只能放在杯口/前高有效突破处。
- 不得把杯柄合并为圆弧底、旗形或箱形整理。

### 8. 岛形底与塔形底的后续确认

- 形态识别与后续确认分开处理；两者都必须先满足自身结构定义。
- “突破口”是形态右侧的有效阻力边界：岛形底使用第二个缺口后岛形区的上边界，塔形底使用右侧大阳线/平台的突破边界。
- 确认条件满足任一项即可：
  1. 收盘价超过突破口至少 3%；或
  2. 突破后连续 3 天收盘价站在突破口上方。
- 未满足上述任一条件时，前端显示为 `candidate`，不得显示为已确认形态或买点。
- 该规则不是岛形底或塔形底的结构构成条件；它只决定候选何时升级为 `confirmed`。

## 七、前端显示与去重规则

- 同一 `pattern_id + start + end` 只显示一条标签；
- 后端同时返回正式名和兼容别名时，以正式 `pattern_id` 为准；
- `candidate` 使用较弱颜色或虚线；
- `confirmed` 使用正式颜色和实线；
- `degraded` 显示“背景削弱”提示，不得当作强信号；
- `invalidated` 默认隐藏主标签，但允许在详情页查看失效原因；
- 前端不得根据形态名称自行推断买卖指令，形态只提供结构和方向信息。
